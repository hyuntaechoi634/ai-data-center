# AI data-center gcamdata overlay

This directory is the public authoring source for the GCAM v9.1 AI
data-center extension. Public files use descriptive names. GCAM's established
chunk and extdata identifiers remain only as a deployment compatibility
contract in `filename-map.csv`.

> Publication gate: the local rebuild is complete, but the calibrated regional
> demand evidence chain includes values derived from restricted BNEF material.
> The affected local files are ignored by Git and checked by
> `provenance/verify_publication_boundary.py`. Review
> `provenance/PUBLICATION_REVIEW.md` before any public push. A reproducible
> public release still requires a reviewed open-data replacement profile.

## Contents

- `chunks/`: 11 R chunks for compute production, trade, demand, XML output,
  accelerator supply, and manufacturing water accounting.
- `data/locked/`: 8 reviewed CSV inputs and one fixed scenario XML that are
  not produced by the generators.
- `data/generated/`: 26 derived CSV inputs rebuilt by the public generators.
- `generation/`: portable generators and the complete compact input closure.
- `provenance/`: active calibrated and preserved prelaunch 45-file manifests,
  plus generation and supplemental-input manifests.
- `filename-map.csv`: descriptive public path to conventional GCAM path.
- `supplemental-file-map.csv`: the separately locked DAC scenario overlay
  needed by the run configurations.
- `deploy.py`: deployment and building-service integration.
- `verify.py`: SHA-256 verification.

The 45 mapped files consist of 11 R chunks and 34 CSV files. Of the CSVs, 24
come from the main compute-input generator, 2 come from the demand-scenario
generator, and 8 are locked reviewed inputs.

The 45-file frozen source layer does not include `dac_ssp2_adv5.xml`. That
file was previously carried into labeled builds by an uncleared XML directory.
It is now explicit as
`data/locked/scenario-overlays/direct-air-capture-advanced.xml`, with its own
map and manifest. A complete public gcamdata snapshot therefore contains 226
XML files: 225 generated by gcamdata and this one fixed scenario overlay.

The regional 2025 demand calibration is frozen to the audited brp7d8 S7
foldback hash used to build `xml-brp7d8-cal`. It is byte-reconstructable from
the preserved foldback evidence with
`generation/reconstruct_frozen_calibration_seed.py`. The prelaunch hash and
full 45-file prelaunch manifest remain in provenance so the calibration chain
can be audited without reading a mutable run tree.

## Rebuild and deploy

Run from this directory:

```bash
python3 verify.py
python3 generation/regenerate.py
python3 deploy.py --apply
./build-gcamdata.sh public-baseline
```

From the repository root, verify the publication boundary separately:

```bash
python3 input/gcamdata/ai-data-center/provenance/verify_publication_boundary.py
```

This check fails if a restricted path is tracked, staged, or present as an
unignored untracked file. It does not certify redistribution rights and does
not substitute for an open-data release profile.

`regenerate.py` is a read-only byte comparison by default. Use
`regenerate.py --write` only when intentionally accepting new generated
outputs. It never rewrites the locked inputs or R chunks.

`deploy.py --apply` copies all mapped files into the surrounding gcamdata
package. It also applies the required GCAM v9.1 building-service integration
to `zenergy_L244.building_det.R`. The script refuses unknown versions of that
core chunk. The energy `zenergy_L232.other_industry.R` chunk remains stock;
only the separate manufacturing-water chunk is replaced.
It also deploys the locked DAC scenario overlay to the conventional filename
expected by existing run configurations.

The build script refuses to overwrite an existing labeled XML snapshot.
It requires all 226 XML files to match
`provenance/brp7d8-cal-xml-manifest.sha256`. Set `RSCRIPT` if the required R
executable is not on `PATH`.

The ready-to-run public snapshot is installed as
`input/gcamdata/xml-ai-data-center-calibrated/`. Runtime policies,
configurations, solver, and restart assets are documented in
`exe/ai-data-center/README.md`.

## Naming and hashes

The checked-in public files are byte-identical to the calibrated brp7d8 source
layer, so their contents can still carry conventional names such as `A280` or
`L1280`. Those identifiers are part of GCAM's data and precursor interface.
The descriptive filename is the public-facing name, while
`filename-map.csv` records the exact reversible translation.

Run `python3 verify.py` after any copy, move, archive extraction, or checkout.
Run `python3 generation/regenerate.py` to confirm that all 26 derived CSVs
and the demand-axis diagnostic table reproduce byte-for-byte.
Use `python3 verify.py --xml-snapshot <directory>` to verify a rebuilt XML
snapshot against every calibrated brp7d8 XML hash.

## Reproducibility boundary

This directory covers the gcamdata authoring layer. Derivation records,
scenario-assumption audits, manuscript materials, and the local paper library
are stored under the repository-root `analysis/research/` tree, which is
ignored by Git because it is not a runtime dependency. Run
`python3 analysis/research/verify-research.py` from the repository root to
verify that local archive.

The source run matrix remains read only and is not moved or modified. The
world socioeconomics XML included under `generation/inputs/` is a compact
generation input snapshot, not a complete GCAM XML build.
